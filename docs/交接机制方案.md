## 1. 现状与差距

| 主题 | 现状 | 差距 |
|---|---|---|
| 交接触发 | 模型回复中行首 `@agent` → `parseMentions` → 扇出（`execution.js`） | 只有"传给另一个 agent"一种出口，没有"持球等待""交还用户" |
| 对象选择 | 解析器只管格式，不教模型怎么选 | 缺"能自决→hold→@agent→@用户"的决策规则注入 |
| 交接格式 | 行首 @ + 下一行描述；首尾放置、最多 2 个、不可 @ 自己（`mention.js`） | 缺 `@用户`、`[持球]` 句柄与对应校验 |
| 球权语义 | 无显式模型；@ 即扇出 | 无接/退/升三选一、无"第一人称"约束、无死锁与矛盾处理 |
| 协作模式 | `mention.mode = parallel`，但 prompt 里只有一句 modeLabel | 并行模式未禁用 @ 路由；串行模式未声明"第 N 只"约束（已有 summonSeq 可复用） |
| 防循环 | 乒乓警告 2 / 阻断 4（按轮内存计数）、`max_hops=6`、`summon_max_per_agent=4`、`max_spawns_per_turn=6` | 缺"实质工作重置"、深度 15、用户消息重置的显式语义（后者已天然成立） |
| 内容传递 | 六段式增量上下文 + delivery_cursor + Warm/Cold（`context-assembler.js` / `incremental.js`） | 已满足，仅需补充交接相关的两个段落（SOP / 持球说明） |
| SOP 衔接 | 无 | 全部缺失 |
| Session 衔接 | `--resume` + `cursor_seq` + profile_version 作废 | 缺"上下文将满时主动封存 + 五段式交接笔记 + capsule" |
| 失败处理 | 子调用失败 → 父级拼接时跳过，写 `[部分失败]` 系统消息 | 缺"通知调用者决策"、缺中断时保留已输出部分文本 |

## 2. 总体模型：一轮内的状态机

```
收到消息（用户 或 上一位 agent @）
        │
        ▼
[接球] 读六段式上下文（来源标识/模式声明/导航头/触发原文/未读历史/系统提示）
        │
        ▼
[能自决吗？]──能（翻代码/读文件即可）──► 自己做完 ──► [三选一]
        │不能
        ▼
[传球三选一]
  ① 另一只 agent 能做 → 行首 @agent（+ 下一行任务描述）
  ② 等外部条件     → [持球:原因]（不 @，不进转交链）
  ③ 只有用户能做   → 行首 @用户（回传终端，链终止）
        │
        ▼
[球权检查] 声明持球/交接必须第一人称；禁止"你等着"；矛盾必须 push back 后立刻行动
        │
        ▼
[防循环] 实质工作重置 / 乒乓阈值 / 深度 / 目标上限
        │
        ▼
结束本轮（交接完成、收尾、或持球等待）
```

核心不变量：**@ 是球权转移的唯一动作**。没有 `@agent` / `@用户` / `[持球]` 三者之一，球权没有转移，本轮就是"收尾"。

## 3. 交接的触发

### 3.1 触发来源

1. **用户消息**：行首 `@agent`（可多个，最多 `user_max=2`）→ 直接扇出（现状，不改）。
2. **agent 回复**：`_extractMentionsFromReply` 解析行首 @ → 扇出（现状）。
3. **新增：控制标记**（与 @ 同级解析，只在行首、只允许出现在首/尾）：
   - `@用户` → 交还用户，链终止；
   - `[持球:原因]` → 持球等待，不进转交链，记录状态。

### 3.2 校验规则（沿用并扩展 `mention.js`）

- 行首 @ 才算；代码块/表格/引用里的 @ 不识别（已有）。
- 每个 @ 必须带下一行描述（已有）。
- 最多 2 个不同目标、不能 @ 自己（已有）。
- `@用户` 不参与"最多 2 个 agent"的计数（它是终端目标）。
- `[持球]` 与 `@` 互斥：同一轮既有 @ 又有持球标记 → 报格式错误，忽略本轮 @（写系统提示）。

## 4. 交接对象的选择（传球三选一决策树，L3）

注入到**静态身份层**（`src/prompt/templates/context/pass_decision.md`，已存在"传球决策树"段落，直接改写扩充；该段位于六段式 [系统提示] 内，每轮随增量上下文注入）：

```
先问自己：这件事我能自决吗？
- 翻代码、读文件、跑只读命令就能确认的 → 自己做，做完按规则传下一棒。
- 做不了，进入三选一：

① 另一个 agent 能做 → 行首 @对方（描述写在下一行）
   · 评审完 → @作者修复；修完 → @评审者确认；合并完 → 停（链终止）；
     功能收尾（feature close）→ @愿景守护（若配置了守护角色）。
   · 跨会话特例：目标不在当前会话，不能直接 @；先列出会话坐标，
     再把证据/结论写到目标会话（后续能力，P3 可选）。

② 等外部条件 → [持球:原因]
   · 不自动轮询：记录持球状态，本轮结束；下一条新消息（用户或任一 agent）到来时解锁继续。
   · 已有结构化回调的，回调到达即可作为新消息解锁，不必写额外标记。
   · 需要跑本地命令 → 命令结束后把结果作为新消息继续（命令托管）。

③ 只有用户能做 → 行首 @用户
   仅限硬条件：不可逆操作（删数据 / force push / 合并第三方 PR）、
   愿景级决策（改愿景、砍功能、开新方向）、多 agent 僵局（2+ agent 两轮无共识）。
```

**外部条件不可投射**：云端 codex、GitHub bot、PR check、CI、长构建、外部 webhook 都不是本地 agent，不能 @ 成 agent 句柄，只能走选项 ②。

## 5. 交接格式

### 5.1 标准格式（模型 → 模型）

```
@迪普斯克
请复核这段迁移脚本的幂等性

（以上为行首 @ 与下一行描述）
```

- @ 块只能放回复最前端或最末端（已有）；
- 每个 @ 的描述取下一行直至下一个 @ 行/空行（已有）；
- 一次最多 2 个目标（已有）。

### 5.2 交还用户

```
@用户
需要你确认是否允许 force push 到 origin/main
```

解析为终端目标：不再 spawn agent；`_runAgentWithHandoff` 返回 `{ok:true, terminal:true}`，父级拼接内容后结束链。

### 5.3 持球等待

```
[持球:等待 CI 结果]
```

- 该行不产生转交；本轮结束；
- 记录到 `tasks/<id>/messages.jsonl`（`kind='hold'`），并在会话里展示"X 正在等待：原因"；
- 下一轮任意新消息（用户或 agent）到达时自动解除持球状态。

## 6. 交接时的球权语义

写进 [系统提示] 与 [模式声明]：

1. **@ = 球权转移**：行首 `@句柄` 即把球交给对方，自己不再行动。
2. **接球后必须三选一**：接（继续做）/ 退（退回上一位 agent，说明原因）/ 升（升级给用户）。
3. **球权只有第一人称**：只能声明"我持球/我交给谁"，不能声明"你持球/他在做"。没有 @、没有 [持球] 就是没收球也没传球。
4. **球权死锁禁止**：收了球却说"你等着 / 你别动" = 非法；做不了就退回（@上一位）或升级（@用户）。
5. **矛盾处理**：收到 @ 但对方说"我在动" → 视为矛盾；必须 push back（指出冲突）并立刻接/退/升，不允许沉默。
6. **诊断 ≠ 解决**：只说"这里有问题"而没有任何 @/[持球] = 球还在地上，本轮判为未完成（系统提示补一句"本轮未交接"）。
7. **等外部条件不投射**：见 §4。

实现落点：

- 规则文本：`templates/context/pass_decision.md` + `templates/context/ball_check.md`（已有"接力棒在你手里…"可扩充）。
- 解析校验：`mention.js` 新增 `terminal`（`@用户`）与 `hold` 结果类型；`execution.js` 按结果分支。
- "球还在地上"检测：一轮结束且无任何交接动作、内容又不像收尾（启发式：包含"你/请/需要你"等指令性措辞）→ 写系统提示；不阻断。

## 7. 交接的协作模式

| 模式 | 语义 | 注入文案 | @ 路由 |
|---|---|---|---|
| serial（串行） | 你排在第 N 位，能看到前面 agent 的回复 | "你是本轮第 {{summon_seq}} 只被召唤的 agent（串行接力模式），请注意前面 agent 的回复" | 允许 |
| parallel（并行） | 各 agent 独立回答同一问题 | "并行模式——独立思考；@句柄在并行模式下无路由语义，不要互相 @" | **禁用**（解析到 @ 时忽略并写系统提示） |

- 配置开关：`config/mention.yaml → mention.mode`（现值 parallel）。
- 实现：`execution.js::_executeTurnWithJobs` 判断 mode；parallel 时 `_extractMentionsFromReply` 结果直接丢弃且不启动分支；
- `summonSeq`（已有）用于串行模式的"第 N 只"。

## 10. 交接的 SOP 衔接

### 10.1 数据

`tasks/<taskId>/workflow.json`：

```json
{
  "workflow_id": "feat_128",
  "stage": "review",
  "history": [{"stage":"dev","at":"2026-11-17T..."},{"stage":"review","at":"..."}]
}
```

`config/workflows.yaml`：阶段 → skill 映射

```yaml
workflows:
  stages:
    dev:      { skill: null }
    review:   { skill: "request-review" }
    fix:      { skill: null }
    merge:    { skill: null }
    close:    { skill: null }
  transitions:
    review: author      # review 完 → @author（回到作者修复）
    fix:    reviewer    # 修完 → @reviewer（回到审查者确认）
    merge:  stop        # 合并完 → 停（链终止）
    close:  guardian    # 功能收尾 → @愿景守护（若存在）
```

### 10.2 注入

- 每轮在 [系统提示] 前追加一行：`SOP: <workflow_id> stage=<stage> → load skill: <skill>`；无工作流时省略。
- 阶段衔接映射以提示形式给出（不强制），最终的 @ 仍由模型按 §4 决策树选择。

### 10.3 告示牌

新增内置工具 `update_workflow`（`skills/update_workflow.md` + 执行模块），参数 `{ stage, note }`：

- 更新 `workflow.json` 并写 messages（`kind='display'`，不投递）；
- 下一棒的增量上下文里能看到最新阶段（下一轮注入时读取）。
- 工具描述限定：只用于推进/同步阶段，不用于业务动作。

## 11. 交接的 session 衔接

### 11.1 触发时机

1. **上下文将满**：组装 prompt 时估算 token（字符/2）接近 `model_cap × 0.8` → 本轮结束后自动封存；
2. **agent 主动请求**：输出中出现行首 `[SESSION_HANDOFF]` → 在干净断点封存；
3. **resume 失效**（`SESSION_NOT_FOUND` / profile 变化）→ 强制封存并重建。

### 11.2 封存产物

`tasks/<taskId>/handoff/<agent>-<timestamp>.md`（五段式）：

```
# 交接笔记（未来的自己）
1. done：已完成的事
2. worktree：涉及的文件/目录
3. commits：相关提交
4. nextSteps：下一步要做什么
5. gotchas：踩过的坑/注意事项
```

`tasks/<taskId>/handoff/<agent>-capsule.json`（continuity capsule）：

```json
{
  "a2a": {"chain": ["用户","克劳德","迪普斯克"], "depth": 2, "summon_seq": 2},
  "ball": {"holder": "迪普斯克", "pair_pingpong": {"克劳德|迪普斯克": 2}},
  "cursors": {"delivery_cursor": 42, "cursor_seq": 42},
  "workflow": {"workflow_id": "feat_128", "stage": "review"},
  "created_at": "..."
}
```

### 11.3 恢复（bootstrap）

- 新 session 首轮（`isFirstCall`）或 resume 失效后：把**最近一份交接笔记**作为 `[交接笔记]` 段 + capsule 的球权/链位置注入 ZONE A（一次性，随首轮 prompt）；
- `delivery_cursor` 保持不变（已投递消息不重复）；`cursor_seq` 归零重建 session；
- 注入后手写一条系统消息"已从交接笔记恢复（<时间>）"，便于审计。

## 12. 交接的失败处理

三条路径（`execution.js::_runAgentWithHandoff`）：

### 12.1 成功

回复完成 → `_appendConversation` 落库 → 解析 @ → 扇出子调用（现状）。同步 await 即"enqueue + 唤醒"。

### 12.2 失败（本次 agent 调用失败）

- 写系统消息 `[转交失败] <agent>：<原因>`（已有类似"部分失败"，细化到单条边）；
- **通知调用者决策**（新增，可配置）：
  - `notify`（默认）：只记录，父级照常拼接成功子结果；
  - `redecide`（可选）：把失败信息回给上一棒 agent，追加一次"你决定：重试 / 换人 / 升级"的调用（每个失败最多 1 次，受 `budget` 限制，**不**计入乒乓计数，避免失败回传形成循环）；
  - `none`：静默跳过（现状）。

### 12.3 中断（用户停止 / 被 steer）

- 不继续 A2A 链（不扇出子目标）；
- **已输出的部分文本仍然持久化**：当前只在流式气泡里，方案要求中断分支把已收到的 `result.partialText` 写入 messages（`kind='chat'`，前缀 `[中断]`）与 conversation，避免用户刷新后内容消失；
- `TurnExecutionStore` 等价物：本轮 turnCtx 记录 `status='interrupted'`，写 CollabLogger `handoff_interrupted` 事件。

## 15. 验收场景

1. **三选一**：agent 遇到"需要用户授权 force push"→ 输出 `@用户` + 说明；链终止，不 spawn 任何模型。
2. **持球**：agent 需要等外部 CI → 输出 `[持球:等待 CI]`；不扇出；前端显示等待状态；用户任意新消息解锁。
3. **球权死锁**：agent 回复"你等着，我稍后处理"且无任何 @/持球 → 系统提示"本轮未交接（球权未转移）"，不阻断。
4. **实质工作重置**：A↔B 来回 3 次，但每次 A 都有 >200 字实质输出 → 乒乓计数被重置，不触发阻断；第 16 跳触发深度上限。
5. **并行模式**：`mode=parallel` 时 agent 输出 @ → 忽略并写系统提示"并行模式下 @ 无路由语义"。
6. **失败回传**：B 调用失败 → 系统消息 `[转交失败]`；`failure_policy=redecide` 时 A 收到失败信息并做出"重试/换人/升级"之一（最多 1 次，不计乒乓）。
7. **SOP**：`workflow.json stage=review` → prompt 含 `SOP: feat_128 stage=review → load skill: request-review`；`update_workflow` 推进到 fix 后下一棒的注入随之变化。
8. **Session 封存**：上下文接近上限 → 生成五段式交接笔记 + capsule；重建 session 后首轮 prompt 含 `[交接笔记]` 与球权/链位置，`delivery_cursor` 未回退。

## 16. 已拍板的决策

| 决策点 | 结论 |
|---|---|
| `hold_ball` 是否自动轮询 | **不轮询**：只记录持球状态，等待下一条新消息解锁（不持续烧进程/凭证） |
| `@用户` 句柄字面量 | **`@用户`** |
| A2A 深度上限 | **15**（`max_a2a_depth=15`，`max_spawns_per_turn` 提到 16） |
| SOP 配置形态 | **静态映射 + 任务只存 stage**：`config/workflows.yaml` 存阶段→skill 映射与衔接规则，`tasks/<id>/workflow.json` 只存 `workflow_id / stage / history` |

剩余待定项：**失败回传策略**。当前文档默认 `failure_policy: notify`（只记录 `[转交失败]`，父级照常拼接成功结果）；若希望上一棒能决定"重试/换人/升级"，改为 `redecide`（每个失败最多 1 次、不计乒乓）。实现时先按 notify 落地，需要时改配置即可。
